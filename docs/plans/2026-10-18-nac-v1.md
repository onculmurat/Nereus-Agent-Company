# NAC Spike + v1 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify the three risky Claude Code mechanisms in a throwaway spike, then build NAC v1: a Claude Code plugin with 11 core role agents, the lead prompt, persistent `team/` memory and mailbox, the escalation ladder, `/nac:setup`, and the EN/TR manual.

**Architecture:** All behaviour that must be reliable lives in small zero-dependency Node.js libraries under `scripts/lib/`, exposed through CLIs (`scripts/*.js`) and hooks (`hooks/*.js`). Agents, skills, commands and the lead prompt are Markdown that tell the model to call those CLIs, so state never depends on model memory. Every hook is a no-op outside a NAC project.

**Tech Stack:** Node.js ≥ 20 (ESM, `node:test`, `node:util.parseArgs`), no npm dependencies; Claude Code plugin format (`.claude-plugin/`, `agents/`, `skills/`, `commands/`, `hooks/hooks.json`).

**Spec:** `docs/design/2026-10-18-nac-design.md` (approved 2026-10-18).

## Global Constraints

- All repository content (folders, file names, role names, instructions, config keys, code comments) is English.
- Plugin name `nac` (so commands are `/nac:<name>`, agents `nac:<role>`); marketplace name `nereus-agent-company`. *(Plan call: the spec names the product `nereus-agent-company` and the command `/nac:setup`; the plugin name sets the command namespace, so the plugin is `nac` inside the `nereus-agent-company` marketplace.)*
- Node.js ≥ 20, ESM (`"type": "module"`), zero runtime and dev dependencies; tests use `node --test`.
- Must work on Windows, macOS and Linux: use `node:path`, never hand-built separators; no `:` in generated file names; accept CRLF in every Markdown/JSON file read.
- Hooks: always exit 0 with no output when the working directory is not inside a NAC project (no `team/config.json` found walking up), or when stdin is empty or not JSON. Only exit 2 where this plan says a hook blocks.
- Single writers: only the lead writes `team/decisions.md` and `team/work/board.md` (through `scripts/board.js` / `scripts/decisions.js`); everything else is file-per-item.
- Nothing is deleted unless its thread outcome is in `team/decisions.md` under `## Decided`.
- Outward or paid actions (push, merge, publish, deploy, purchase) are never performed by any script; prompts require explicit owner approval.
- Parts adapted from superpowers keep `Copyright (c) 2025 Jesse Vincent` (MIT) in `NOTICE`.
- `README.md` and `README.tr.md` change in the same commit.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push, no merge without owner approval.

## Review Focus

1. Project path with spaces (e.g. `D:\Projects\Personal Vault`) — hook commands and CLIs must work; `${CLAUDE_PLUGIN_ROOT}` is always quoted. Pinned in Task 7 and Task 13.
2. Hook runs in a non-NAC project or receives malformed stdin — must exit 0 silently and never block the session. Pinned in Task 6 and Task 7.
3. Files saved with CRLF line endings (Windows, git autocrlf) — board, decisions and message parsers must read them identically. Pinned in Task 3 and Task 4.
4. Existing `.claude/settings.json` with its own `env`, `hooks` or invalid JSON — setup merges, never overwrites, and aborts on invalid JSON. Pinned in Task 8.
5. The same message recorded twice (live hook plus helper, or hook retried) — exactly one file per message id. Pinned in Task 3 and Task 7.

## Shared formats (used by several tasks)

Message file `team/work/mailbox/<thread>/<stamp>-<from>-to-<to>.md`, `<stamp>` = UTC `YYYYMMDDTHHmmssSSSZ`:

```
---
id: <id>
from: <role>
to: <role>
thread: <thread>
date: <ISO 8601 UTC>
state: unread | read | closed
---
<body>
```

Message header convention (agents put it as the first line of every `SendMessage` body): `[thread:<thread-id> from:<role>]`. Thread ids match `^[a-z0-9][a-z0-9-]{0,63}$`; anything else is rejected (no path traversal). Missing thread → `general`.

`team/work/board.md`:

```
# Board
phase: 0

## T-001: <title>
- owner: <role>
- status: todo | in-progress | review | done | blocked
- rounds: 0
- model: <haiku|sonnet|opus>
- commits: <sha, sha>
- handoff: team/work/handoffs/T-001.md
```

`team/decisions.md`:

```
# Decisions

## Open questions

### Q-001: <title>
- source: <text>
- status: <text>
- impact: <text>
- blocking: yes | no
- thread: <thread-id>

## Decided

### D-001: <title>
- question: Q-001
- answer: <text>
- date: YYYY-MM-DD
- link: <path or url>
- thread: <thread-id>
```

Hand-off note `team/work/handoffs/<task-id>.md`; escalation record `team/work/escalations/<entry-id>-r<round>.md`.
